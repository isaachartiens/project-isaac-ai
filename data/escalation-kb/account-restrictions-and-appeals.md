# Account Restrictions & Appeals — Tier 1 Agent Guide

**Document Type:** Internal SOP
**Audience:** Tier 1 Support Agents
**Last Updated:** 2026-10-01
**Version:** 3.0

---

## Purpose

Guide for handling account restriction inquiries and appeals. Tier 1 agents can explain restrictions and process initial appeal submissions. Tier 1 CANNOT lift restrictions or make final appeal determinations.

---

## Restriction Types

| Restriction Type | What It Means | Can T1 Lift? |
|-----------------|---------------|--------------|
| Buying Restriction | Cannot make purchases | NO |
| Selling Restriction | Cannot create new listings | NO |
| Full Account Suspension | Cannot access account at all | NO |
| Listing Removal | Specific listings removed | NO |
| Payment Hold | Funds held for review | NO |
| Feature Restriction | Specific features disabled | NO |
| Shadow Restriction | Visibility reduced | NO |

**Tier 1 agents CANNOT lift any restriction. All restriction lifts require Tier 2 or higher.**

---

## Step 1: Identify the Restriction

1. Pull the user's account in OMS (Account Search → email or user ID).
2. Check: Account Status, Restriction Reason, Applied By, Appeal Eligible fields.

**Fraud-related restrictions** → **Escalation Trigger:** Do not discuss details → Escalate to Tier 2.

**Linked account restrictions** → **Escalation Trigger:** Escalate to Tier 2.

**Counterfeit-related selling restrictions** → **Escalation Trigger:** Escalate to Tier 2 Counterfeit team.

---

## Step 2: Communicate with the User

### What You CAN Tell the User
- The general category of the restriction.
- What the restriction prevents them from doing.
- Whether they are eligible to appeal.
- General steps to resolve (if applicable).
- Expected timeline for review (if known).

### What You CANNOT Tell the User
- Specific internal thresholds or metrics that triggered the restriction.
- Details of fraud investigations or security reviews.
- Information about other accounts linked to theirs.
- Which specific reports led to the restriction.
- The identity of who reported them.
- Internal algorithms or automated detection methods.

**Escalation Trigger: User demands specific details you cannot share** → Politely explain confidentiality. If user becomes aggressive or threatens action → Escalate to Tier 2.

---

## Step 3: Handle by Restriction Category

### Buying Restriction — Payment Issues
1. Check for outstanding failed payments or chargebacks.
2. If outstanding balance exists → Inform user of amount owed, direct to payment resolution page.
3. If no outstanding balance visible → **Escalation Trigger: Unexplained payment restriction** → Escalate to Tier 2.

### Buying Restriction — High Return Rate
1. Check return rate (returns / total orders) for last 90 days.
2. If below abuse threshold → Inform user to reduce return frequency. Set 30-day review.
3. If return abuse suspected → **Escalation Trigger: Return abuse pattern** → Escalate to Tier 2. Do NOT accuse user.

### Policy Violation (General)

| Violation Code | Description | T1 Action |
|----------------|-------------|-----------|
| PV-01 | Prohibited item listed | Remove listing, inform user of policy |
| PV-02 | Circumventing fees | Inform user of policy |
| PV-03 | Off-platform transaction | Warn about loss of buyer protection |
| PV-04 | Bidding manipulation | **Escalation Trigger** → Tier 2 |
| PV-05 | Review manipulation | **Escalation Trigger** → Tier 2 Trust & Safety |
| PV-06 | Harassment/abuse | **Escalation Trigger** → Tier 2 Trust & Safety |
| PV-07 | Multiple accounts | **Escalation Trigger** → Tier 2 |
| PV-08 | Counterfeit listing | **Escalation Trigger** → Tier 2 Counterfeit team |

For first-time minor violations (PV-01, PV-02, PV-03): Send policy education notice (AR-POLICY-01). Log communication.

For serious or repeated violations: **Escalation Trigger** → Escalate to Tier 2.

### Selling Restriction — Performance Metrics
1. Pull seller's performance dashboard.
2. Inform seller that selling privileges are restricted due to below-minimum performance.
3. Direct to Seller Performance Help Center.
4. Do NOT share specific threshold numbers.
5. If seller wants to appeal → Go to Step 4.

### VeRO Violation
1. Inform user that a rights owner reported their listing.
2. Direct to VeRO complaint process if they believe report was in error.
3. Do NOT share the identity of the rights owner.
4. **Escalation Trigger: User disputes VeRO claim** → Escalate to Tier 2 VeRO team.

### Full Suspension — Account Compromise
1. Inform user account was suspended for security protection.
2. Direct to account recovery process (requires identity verification + password reset).
3. If recovery completed → **Escalation Trigger:** Escalate to Tier 2 to lift suspension.
4. If recovery fails → **Escalation Trigger:** Escalate to Tier 2.

### Payment Hold — New Seller Review
1. Inform seller that new seller funds are held for review period (14-21 days).
2. Funds released after review if no issues found.
3. If seller has been selling > 30 days and funds still held → **Escalation Trigger: Extended hold** → Escalate to Tier 2.

### Payment Hold — Dispute Under Review
1. Inform seller that funds are held pending dispute resolution.
2. Funds released once disputes are resolved.
3. If no active disputes visible → **Escalation Trigger: Unexplained hold** → Escalate to Tier 2.

### Payment Hold — Verification Needed
1. Identify and communicate what verification is pending.
2. Direct user to verification page.
3. If hold does not lift 48 hours after verification → **Escalation Trigger** → Escalate to Tier 2.

## Step 4: Appeal Process

**Appeal Eligible: YES**
- Direct user to Appeal Form in account settings.
- Inform user: appeals reviewed within 5 business days.
- Advise user to include: explanation, steps taken to prevent recurrence, supporting documentation.
- Log appeal request. Set case status to APPEAL-SUBMITTED.
- Do NOT make any promises about the outcome.

**Appeal Eligible: NO — Within cooldown period**
- Inform user of the date they can submit a new appeal.
- Set case status to APPEAL-COOLDOWN.

**Appeal Eligible: NO — Permanent restriction**
- State "the decision is final and no further appeal is available."
- **Escalation Trigger: User disputes permanent restriction** → Escalate to Tier 2 for confirmation.

---

## Step 5: Common User Scenarios

### User Claims They Don't Know Why They Were Restricted
- Provide general category of reason.
- Do NOT provide specifics if reason involves fraud, security, or another user's report.
- **Escalation Trigger: Missing or unclear restriction reason in OMS** → Escalate to Tier 2.

### User Is Angry or Threatening
- Remain calm and professional.
- **Escalation Trigger: Self-harm threat** → Escalate to Tier 2 Crisis Protocol immediately.
- **Escalation Trigger: Threat of violence or harm to staff** → Escalate to Tier 2 Security team.
- **Escalation Trigger: Legal action threat** → Escalate to Tier 3 via Tier 2.
- If abusive but not threatening → Issue one warning. If abuse continues, end conversation and log.

### User Claims Restriction Is an Error
- If automated → **Escalation Trigger** → Escalate to Tier 2 for manual review.
- If manual → Inform user they can submit an appeal.
- Do NOT suggest the restriction might be wrong.

### User Asks to Speak to a Supervisor
- Inform user you can escalate to a specialist team.
- Do NOT transfer to a specific person or promise a callback.
- **Escalation Trigger: User demands supervisor** → Standard Tier 2 escalation.

---

## Escalation Triggers Summary

**Escalate to Tier 2 (Standard):**
- User disputes automated restriction
- User submits an appeal
- Unexplained or missing restriction reason
- Linked account restrictions
- Verification complete but hold persists
- Extended new-seller payment hold (> 30 days)
- User disputes VeRO claim
- User demands supervisor escalation

**Escalate to Tier 2 (URGENT):**
- Account compromise confirmed or suspected
- Failed account recovery
- User disputes permanent restriction

**Escalate to Tier 2 — Specialized Teams:**
- Fraud-related → Tier 2 Fraud team
- Counterfeit-related → Tier 2 Counterfeit team
- Conduct violations → Tier 2 Trust & Safety
- Review manipulation → Tier 2 Trust & Safety

**Escalate to Tier 3 (via Tier 2):**
- Legal threats related to restriction
- Regulatory complaints about restriction
- Media inquiries
- Restrictions on VIP/public figure/top seller accounts
- Self-harm threats → Tier 2 Crisis Protocol (immediate)
